## Change identity / boundaries

Intent: supply an authenticated, immutable-content handoff to an offline Codex checkout and require a distinct authenticated publication gate. Proposed scope: an explicit exception to the current rule that the *executing agent itself* must retrieve live `main` before authoritative mutation, **only if** the reviewer/agent split below is approved through normal governance. Until that happens, existing LOOM_START_HERE.md, AGENTS.md and change-control STOP instructions prevail. No canon, physics, frozen scientific objects, databases, release or production change. Runtime and CI compatibility: `REVIEW_REQUIRED` for PR #256; Pixel/Windows updater: `UNCHANGED_COMPATIBLE` as long as no updater files change. Governance/process dependencies: `REVALIDATION_REQUIRED` for session bootstrap, scope rules and affected documentation, and for `loom-gate` only if its implementation must change (not proposed). No new agent, token, permission, online connectivity, GitHub workflow, branch protection or automation. Promotion target, if separately approved: protected `main` through ordinary PR/loom-gate; never direct change of policy from a draft.

## Actors / separation of duties

- **Connected verifier**: an authenticated GitHub connector/operator capable of GET on `main`, PR heads, issue and issue-comment bodies. Captures evidence and certifies its provenance; never substitutes chat memory or summary.
- **Offline executor**: Codex task with no GitHub remote; consumes verified complete captured text; checks task-local objects and constraints; writes offline implementation and tests only *after protocol promotion*. Cannot certify current remote state or publish merely by creating a local commit.
- **Publication verifier**: an authenticated GitHub-capable reviewer that repeats remote checks immediately before manual Update branch, confirms exact task-local diff and approval scope, then checks resulting GitHub commit and CI. This may be the same operator as connected verifier but is a distinct independent check, never Codex self-report.
- **Decision authority**: Kevin explicitly approves the final governance change and separately approves any particular release/deployment. Proposal authors cannot self-approve a governance exception.

## Proposed evidence artifact schema

Store a machine-readable manifest plus a text-only content directory under the implementation PR's documentation path. Require: schema_version; repository identity; capture_utc; verifier identity and authenticated-read method; exact immutable `main_commit`; expected implementation `head_commit` and parent `base_commit` plus PR numbers and branch names; immutable source URLs and *Git blob SHA plus SHA-256 of raw UTF-8 bytes* for every content item; source kind (main file, issue, comment, PR metadata); optionality explicitly false unless a rule names an alternative; change class, scope, non-scope; authorization record; expiry/maximum snapshot age specified by approved policy, not chosen ad hoc by executor; and independent publication-check log identifier. Entire original source bytes must be committed verbatim, not only hashes, links, excerpts, model summaries, or reconstructed text. A verified absent optional scoped AGENTS must be recorded as an authenticated absence; inability to read is not evidence of absence. Capture must not contain secrets, credential-bearing URLs or private host authentication data. Canonical encoding, ordering, hash algorithm and manifest schema must be specified in the implementation; an LLM-authored manifest without independently checked source identity is insufficient.

Required source set for Phase 3: `LOOM_START_HERE.md`; `governance/current/LOOM_CURRENT_WORKSTATE.yml`; latest governed status overlay (at capture time); governance baseline, authority model, change control, research boundary; root `AGENTS.md` and every nearest scoped AGENTS for paths to be modified; component-map/dependency policy; compatibility manifest/release metadata and relevant deploy scoped contract; full issue #255; full binding scope comment on PR #251; full PR #256 and #251 metadata including exact refs; and implementation plan. Capture each main file by `ref=<immutable main SHA>`, never a drifting branch URL. If an unanticipated target subtree or dependency appears, STOP and extend/review capture before editing. Verify latest overlay by listing the authoritative directory, not by assuming the dated filename is still latest.

## Proposed deterministic workflow (must be implemented and tested before approval)

1. **Pre-capture**: connected verifier loads the current `main` SHA, authenticates all required GETs, enumerates current status overlays and scoped rules, reads actual contents, identifies class/scope/blocks/dependencies/required tests, checks parent and successor live branch SHA and ancestry, and records an evidence log. Any 401/403/404, incomplete paginated response, conflicting rule, missing required source, freeze or unapproved exception => STOP.
2. **Capture**: retrieve source files at immutable main SHA and immutable issue/comment identifiers; preserve complete raw bytes and Git blob hashes where applicable. Generate manifest using deterministic tooling; independently verify bytes/hash against remote. The manifest records source issue/comment updated_at or immutable content digest and captures the live refs separately. Review capture diff for secrets and unauthorized changes. Do not present hash verification of a locally authored document as verification of GitHub provenance.
3. **Offline task preflight**: on *fresh* task checkout, check `git rev-parse HEAD` equals manifest expected head, parent object exists and is ancestor; check no unexpected dirty changes; validate schema and all local SHA-256s and required content presence; read complete captured rules in mandated order; verify local source tree and nearest AGENTS coverage. Report handoff as `OFFLINE_SNAPSHOT_ONLY`, never `LIVE_GITHUB_VERIFIED`. If handoff itself was added in a new successor commit, manifest must bind the *new* GitHub head commit and earlier implementation ancestor without a circular self-hash; use an externally certified manifest identity and a fresh successor task checkout. Never assume PR #256's historical a0c647f SHA is its current head.
4. **Offline preparation**: only following recorded policy promotion and task authorization, make a scoped diff and run unit/functional/negative tests locally. Do not push to an unverified branch; if Codex lacks remote, task-local commit and manual Update branch is a candidate handoff, not publication. If no functioning manual handoff is available, STOP and preserve a reviewable patch; do not create an alternative PR or remote.
5. **Publication preflight**: before a user presses Update branch, connected publication verifier checks `main` and all specified remote PR heads anew via authenticated reads, re-fetches issue/contract and required changed files for conflicts, checks manifest age per approved window, compares task base and proposed diff, and checks governance promotion status/approval. If main changed, issue/comment changed, heads moved or verification fails, STOP and recapture/review; never silently rebase or replace refs. Do not pretend a check seconds earlier guarantees an atomic push: after handoff, independently verify resulting GitHub commit has expected parent and diff; on race or mismatch quarantine/review, not auto-merge.
6. **Qualification/promotion**: obtain relevant CI and actual test evidence, full reviewer change inventory and explicit scope approval. Only separately authorized merge/promotion may follow normal protected-main controls. Sydney release requires an additional distinct operator decision and live checks; passing this protocol never deploys.

## Proposed fail-closed acceptance matrix (no tests have yet been executed)

Test harness shall use local fixture snapshots and a mock authenticated GitHub adapter, with no live-host access and no credentials in logs. Each negative fixture must return nonzero/block status, clear reason and no mutable output/publish action:

- positive exact main/head/base/complete text/hash/approval fixture => permits OFFLINE_PREPARATION only;
- stale main SHA; moved parent or successor head; mismatched local HEAD; parent not ancestor; dirty checkout => STOP;
- modified source bytes, modified manifest, wrong Git blob SHA, missing text, truncated response, invalid schema, unknown extra target subtree, missing or ambiguous AGENTS => STOP;
- 401/403/404, absent issue/contract, modified issue/comment, outdated overlay, conflicting policy, invalid verifier identity, expired capture => STOP;
- captured credential/token/secret or unauthorized mutation scope, missing human approval, blocked/frozen target => STOP;
- push during offline stage, unreviewed manual Update branch, changed head/main between precheck and resulting GitHub commit, failed CI => STOP or QUARANTINE, never silently PASS;
- a successful *mock* offline preparation still must not be accepted as live GitHub verification, production qualification, release authorization or deployment.

Required test deliverables: deterministic validator implementation, fixtures, full command transcript with exit codes, negative mutation/integrity results, evidence retention/redaction review, and reviewer confirmation that GitHub publication identity and diff match. A prose checklist is not equivalent to these tests.
