# Engineering subtree agent rules

Applies to `engineering/**`.

## Authority

Engineering translates canon into normative technical closure and implementation guidance. It does not silently override canon.

Before mutation:

- identify the governing canon source/amendment set;
- identify the engineering assumption or closure being changed;
- identify runtime/data/3D/media dependents;
- distinguish measured/derived values from fictional postulates and implementation choices.

## Conflict rule

If engineering cannot close under current canon, raise an engineering finding and, if needed, a CCR proposal. Do not quietly edit canon or distort calculations to force closure.

## Cross-subsystem discipline

Changes affecting mass, thermal, geometry, propulsion, operations, HUD/gameplay contracts or runtime architecture must declare downstream invalidation/revalidation.

## Testing

Engineering changes that alter executable contracts require the relevant downstream unit/functional validation before promotion.

## Adoption pause

During Governance Adoption, engineering content changes are paused unless the current workstate explicitly authorizes a governance-only metadata change.
