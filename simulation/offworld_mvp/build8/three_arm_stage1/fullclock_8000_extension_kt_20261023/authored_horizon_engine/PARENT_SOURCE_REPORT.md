# Moon parent-table provenance (TEST_ONLY)

The approved moon pricing rule is **Earth-to-parent** heliocentric transfer geometry followed by authored moon local-leg cost, using the moon's `parent_gm_km3_s2` and `orbit_radius_km`. It does **not** require the moon's own heliocentric position table. In particular, both NEREID and PROTEUS use the independently checked **NEPTUNE** parent table sourced from registered `nep097.bsp` (not the failed `nep098_part-3.bsp` moon kernel). Their own incomplete moon kernels do not exclude them. The price row includes `parent_source_body=NEPTUNE` and `source=registered`. The source label `recovered_phase4e` must appear only when the actual selected source was recovered, never because the moon's separate kernel had been recovered.

DACTYL and SELAM are the two genuine exclusions: neither has the necessary qualified direct source and moon gravity parameters. The other 28 moons are not excluded on the strength of a failed own-body table. Legacy endpoint rejection `UNKNOWN_LOCAL_LEG` is reported as an **existing engine gate**, not silently reclassified as no source or no gravity. The copied grid engine changes only the flight-limit validator; its inherited eligibility gate is intentionally unchanged.

The prior Phase4E kernel statement **"qualified to 2031"** meant that the earlier qualified source coverage/approved use had only been established to that horizon; it did not prove that SPK segment data physically end at 2031. A new scalar SPICE exact-bit independent oracle sampled across the longer table checks that the table values match the chosen source and numerical epoch lattice at those samples. It does **not** independently validate the astronomical truth of the source beyond 2031, certify every unsampled row, or retroactively promote legacy source eligibility to 2057.
