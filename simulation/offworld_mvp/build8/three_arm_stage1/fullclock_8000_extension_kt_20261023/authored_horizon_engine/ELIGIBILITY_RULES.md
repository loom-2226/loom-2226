# Source-eligibility and flight-range audit (TEST_ONLY)

`simulation/offworld_mvp/build8/travel_pilot/on_demand.py:93-99` rejects flight grids whose requested upper limit exceeds 5000 days. This is an input/grid sanity bound, **not** a 2057 table-coverage check. `on_demand.py:158-168` calls `endpoint()` for both bodies before any geometry and `on_demand.py:82-90` delegates to `eligibility.resolve_endpoint`, which checks the *legacy catalog/registry*. That rule can return `UNKNOWN_EPHEMERIS_MISSING` even when an independently checked new numeric table exists, because the new table is not a promoted catalog source. `eligibility.py:151-162` may return `UNKNOWN_LOCAL_LEG` for a moon even though its parent-table pricing route is separately approved. These are different gates, not proof that the new position data are invalid. `on_demand.py:175-185` also requires a `DIRECT` source for the origin; no guessed source may be substituted.

The test-only copy in `engine.py` changes **only** the authored upper flight-range bound and retains the original 5000-day flight-*step* bound. It inherits all other source eligibility, geometry, Lambert and Pareto code from the existing engine. Its scenario is visible, printed and SHA-256 hashed. Any 8000-day price rejected by legacy eligibility remains unpriced and attributed to that gate, rather than silently relaxing source qualification. Its table lookup must fail `NO_DATA` if any sampled arrival lies outside 2026-01-01 through 2057-11-25. No row is silently extended or extrapolated.

An exact grid hash check is necessary but insufficient for price equivalence. Independent price comparisons must also include a giant-planet moon, inner body and outer body and report the first difference. A failed price equivalence blocks treating 8000-day prices as campaign-authoritative.
