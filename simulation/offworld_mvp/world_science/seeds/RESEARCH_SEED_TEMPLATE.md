# Canonical World-Science Research Seed Template

Use this template to extend the same governed empirical baseline.

```text
LOOM SOLAR WORLD SCIENCE RESEARCH CAMPAIGN

TARGETS:
<explicit bodies>

BASELINE:
simulation/offworld_mvp/world_science/lab_v0_1/

HARD RULES:
- GitHub outranks chat.
- Inspect current database/schema/validation before modification.
- Record pre-campaign Git identity and SQLite SHA-256.
- Research remains CANDIDATE until separately admitted.
- No HIDDEN_WORLD or SCENARIO scientific assertions.
- No fictional project sites, deposits, reserves or resource inventories.
- SPICE/JPL/NAIF remain navigation authority; verify identity/frame/coverage.
- UNKNOWN, conflict and competing models are valid.
- Preserve BODY/REGION/FOOTPRINT/LOCAL_SITE/SAMPLE/MODEL_DOMAIN scope.
- Preserve epoch/vertical support where scientifically material.
- Detection != abundance.
- Surface/sample composition != bulk composition.
- R_in_situ != R_accessible != R_recoverable != R_reserve.

RESEARCH:
For each target recover existing LOOM evidence, then independently research authoritative/current physical, orbital, geological, compositional, environmental, thermal, interior, spatial and temporal evidence as supported. Register authoritative spatial products by metadata rather than ingesting giant rasters. Separate observation, derived constraint and model inference.

COVERAGE:
Update coverage using existing semantics. Explicitly identify STILL_UNKNOWN and observational gaps.

WORLD-GENERATOR READINESS:
Classify each target into:
1. REAL / EMPIRICALLY CONSTRAINED
2. SCIENTIFICALLY CONSTRAINED UNKNOWN
3. GENUINELY UNCONSTRAINED
Assess BODY -> REGION -> SITE -> DEPOSIT without generating hidden state.

VALIDATION:
Require FK integrity, provenance completeness, no scope globalization, no hidden-world leakage, no illicit promotion, zero fictional worlds/sites/deposits, and regression preservation of prior bodies.

REPRODUCIBILITY:
Perform two clean post-campaign rebuilds. Require identical SQLite SHA-256. Record pre/post DB hash, schema hash, build-script hash, source-manifest hash, validation result and final counts.

Do not integrate with a numbered build.
Do not commit/push/merge/tag/promote unless separately authorized.
```
