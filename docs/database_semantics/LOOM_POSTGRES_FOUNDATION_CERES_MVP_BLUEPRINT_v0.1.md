**Decision rule.** Gate A applies to descriptive claims. A `QUALIFIED` MVP-A identity may enter this slice only at its documented grain, unit, epoch and accounting basis. `UNRESOLVED` values are absent from PostgreSQL, including from any generic raw/quarantine table or JSON payload. `NOT_APPLICABLE` media, identity and integrity controls do not qualify world claims. Structural keys, endpoint IDs, relationship-key discriminators and operational lineage may be stored as structure, with their **meaning explicitly bounded**; the structural mapping below names the source and evidence for each. Gate B provenance remains `PARTIAL`, C numeric/accounting validation `NOT_TESTED`, and D reproducibility `PARTIAL`; track and resolve each independently. They are not silently converted into extra Gate-A admission criteria. Admission permits a controlled candidate projection, not a release verdict.

The governing boundary is `data/AGENTS.md` and the database interpretation contract. Corrective action before import acceptance: reconcile selected fields against exact source, CIVSTATE self-documentation and the MVP-A qualification record; neither broad table label can admit an unresolved value.

Phase 2B retains planning lanes for country, sector, asset, Earth handoff, workforce, campaign state and other domains. This design neither deletes them nor ports their legacy tables. Historical SQLite files remain intact outside PostgreSQL for forensics and later CIVSTATE remodeling. PostgreSQL is a typed projection, not a new canon authority.

## Proposed foundation

Use four schema namespaces; PostgreSQL version and deployment location remain implementation choices to record with the first code change. No SQLite table is copied wholesale.

| Schema | Responsibility |
|---|---|
| `loom_control` | Append-only source identity, migration, semantic/model versions, candidate snapshot, import run and row lineage. It stores **keys and metadata only**, no source descriptive payload. |
| `loom_world` | Typed cross-slice entity, facility, noun and physical-reference identity. Its IDs can support later LOOM bodies and facilities. |
| `loom_civ` | Typed subject registry and selected relationship tables, with explicit endpoint foreign keys. It does not turn a graph edge into ownership or legal authority. |
| `loom_ceres` | Only admitted 2226 Ceres measures and a bounded pressure-record count. Derived display calculations live in a versioned projection, not copied into source tables. |

All imported domain rows include `snapshot_id uuid NOT NULL` and `import_batch_id uuid NOT NULL`. Every key and FK below is composite with `snapshot_id` unless stated otherwise. Import batches are immutable after acceptance; a new source/model/semantic version creates a **new snapshot**, never an in-place rewrite of an old one. `snapshot_id` is a projection identity, not an epoch. All 2226 modeled rows carry `year smallint = 2226`; WORLD physical reference rows have no invented measurement year.

The first implementation should declare PostgreSQL roles: migration owner can change DDL; importer can insert only into candidate snapshots and approved tables; Ceres reader can select only versioned, allowlisted projection views/functions; no Ceres request path can select `loom_control.row_lineage` or original SQLite. A source hash or row key establishes identity and replay context, not semantic or canon approval. Because `row_lineage` is generic metadata, enforce a database constraint or importer allowlist limiting `target_table` to the exact typed tables below; it cannot become a raw payload store.
