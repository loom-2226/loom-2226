## 1. Substrate and ownership

PostgreSQL is proposed as durable relational authority for scientific constraints and named fictional WORLD/location state. It is not an alternate live 6D kernel. A future integration must choose one authoritative writer at the transaction boundary; 6D in-memory stores remain authoritative for existing frozen executions. Persisted projections are evidence until a later approved 6E DLD explicitly establishes runtime ownership. Importing an original record neither repeats its action nor promotes it into an Agent fact.

Required database target: PostgreSQL 18, UTF8 encoding. The DDL is an exactly-once fresh-database design script under a trusted superuser DBA. Existing role/schema/extension collisions fail rather than silently accepting unknown definitions. pgcrypto is the only required extension, used to check exact byte SHA-256. PL/pgSQL guards validate integrity; they contain no scheduler, balance reducer, generator or policy executor. PostGIS is not required.

Namespace separation is physical and security-relevant:

| Schema | Authority and contents | Agent read path |
|---|---|---|
| wa_meta | reviewed design version, pinned source snapshot, forensic legacy rows, lexical units and narrow domains | domain usage only |
| wa_geo | named real-body identity, frames, scoped spatial anchors, explicit supports | none directly |
| wa_nav | navigation authority product identity and coverage | none directly |
| wa_science | REAL empirical observations, samples, assertions, material evidence and science governance history | none directly |
| wa_world | SCENARIO generation descriptors, consumed constraints, hidden properties, sites and finite deposits | forbidden |
| wa_run | REALIZED run identity, original typed records, causal envelopes, physical/domain projections | forbidden |
| wa_info | consumption, admission, lawful possession, belief, decision and sanitized worker facts | private |
| wa_agent_api | the bounded current-snapshot and fact projections | explicit per-principal projection |
| wa_crypto | integrity function extension | no Agent usage |

A schema is not a simulation subsystem. These namespaces let database privileges express the FRD firewall. REAL scientific ontology is not the same axis as REAL/SCENARIO/REALIZED context. The four preserved science values remain literal constrained strings: REAL_EVIDENCE, MODEL_INFERENCE, DERIVED, REALIZED_OBSERVATION. The baseline defines the last as an empirical-context observation slot, not generated hidden truth; it has zero populated rows. A simulation mission observation belongs only in wa_run.observation with REALIZED(run_id). No spelling-based promotion or mapping between these two namespaces is allowed.

## 2. Identity, immutability and ordering

All new UUIDs are supplied by a trusted importer/generator; there is no database random UUID, serial ID or sequence. Use UUIDv5 namespace `fc7bc6cd-f41f-5293-ab79-312760b5cedc` with UTF8 names consisting of an unambiguous length-prefixed tuple `(object_kind, authority_namespace, semantic_key, revision)`; each length is byte length and each component is retained exactly. No Unicode normalization, case folding or locale-sensitive ordering. Existing 6D `run_id`, artifact refs, receipt IDs and envelope IDs remain exact text and are never replaced by UUIDs.

Body identity is durable by catalog key, independent of source revisions. For preserved bodies use `authority_namespace=LOOM_BODY_V1`, existing body_id as semantic key, revision `IDENTITY_V1`. Regions/locations use body key plus region_key; they are stable spatial identity only. Revisioned evidence/source/model/policy identities include their exact existing semantic key and frozen source snapshot digest or governed revision. Numeric SQLite IDs remain forensic source keys, not global identity. A second import with the same semantic tuple must either match exact payload or fail; no last-write-wins collision handling. New body/location revisions that change actual meaning require a new semantic identity, with explicit relation, not reuse of an old UUID.

A run can bind many body realizations within its one scenario. System/orbital locations can describe navigation placements without manufacturing a body realization or geology; only actual physical-WORLD consumption requires the explicit appropriate binding. Composite keys and foreign keys enforce same scenario, run, world and body wherever typed physical associations cross tables. Cross-body scientific lineage is allowed as lineage, not scope authorization. Explicit extrapolation stores source and target bodies/supports; no cross-body generation binding is legal without that scientific warrant.

All authority records and histories are append-only. UPDATE, DELETE and TRUNCATE are rejected by triggers, including evidence, original byte records, generator descriptors, physical history and trace. Corrections are new versions plus governed supersession/reconciliation. The sole mutable table is principal_binding: access can be revoked without rewriting simulation history. Security ACL changes do not cause simulation events. A trusted DBA can alter schema/disable guards; that administrator is outside the Agent epistemic threat model and must remain under release governance.

All authoritative writes require SERIALIZABLE transactions. Deterministic imports are single-writer or retry aborted transactions using the same precomputed IDs and records. A retry may not rerun a simulation decision or consume a new random draw. Per-run advisory locking validates insertion order but creates no simulation order. Database wall time appears only in explicit administrative installation metadata. Original source acquisition/date lexemes are not database insertion timestamps.

Canonical ordering: C-collated exact semantic strings; UUID byte order for association tie breaks; scientific revisions by explicit revision identity; trace by `(run_id,event_ordinal)`; edges by `(edge_role,edge_ordinal)` with the original tuple archived; all output tables by their full primary key. Derived event_ordinal is the existing causal_envelopes list position starting at zero, an export index, never an additional scheduler input. Causal envelope IDs retain the original one-based suffix.

## 3. Spatial support

Body contains only real celestial identity, class and optional original parent association. Body_system/system_member supplies named multi-primary membership (including circumbinary cases), not a numerical orbit. Original null parents remain null: migration must not infer Earth/Sun parents merely because astronomy suggests them.

Location contains only spatial anchors with exactly one real body or named-system anchor: REGION, SITE, FOOTPRINT, MODEL_DOMAIN, LOCAL_FEATURE, ORBITAL_DOMAIN, ATMOSPHERIC_DOMAIN, INTERIOR_DOMAIN or RING_DOMAIN. A system anchor represents shared/barycentric/circumbinary orbital space without pretending a barycenter is a celestial body. Geometry uses the same exactly-one body/system anchor rule. Its origin explicitly distinguishes empirical identification, scientific model domain and authored spatial anchor. An authored site name on the real Moon means a coordinate/domain anchor; it does not claim an actual lunar mine, settlement or observed deposit exists. Real geography is shared across scenarios, while local fictional physical realization is beneath a world_id.

There is no forced single-parent tree. CONTAINS is an acyclic directed spatial relation, OVERLAPS/ADJACENT are canonical unordered pairs, ASSOCIATED is a declared directional relationship. Relations require warrants and never grant scientific extrapolation. A relation spanning different frames/anchors requires an explicitly characterized relationship/transform warrant in the validator; the SQL relation records no automatic physical containment calculation. Nested regions, overlapping instrument footprints, a project spanning several regions and shared infrastructure require no reparenting. A region is not a property container whose assertions inherit into every child.

Frame identifies NAIF or other governed authority definitions, body-fixed/local/inertial status, units and epoch. A body-specific or system-specific frame must match geometry anchor; a shared inertial frame can have neither body_id nor system_id. Local frame anchors may be body or named-system; BODY_FIXED requires a body. Local frames require an explicit body/system anchor and pinned definition; unresolved legacy frame names remain UNRESOLVED. No automatic rotation, longitude convention, gravity datum, spherical radius or Earth reference system is supplied.

Geometry records POINT/LINE/POLYGON/VOLUME/MESH/FOOTPRINT/ORBITAL_REFERENCE/UNCHARACTERIZED. Only points use scalar coordinate slots, interpreted by encoding_ref and coordinate_semantics, never anonymous lat/lon. Nonpoint shapes use source product locators, format/encoding, frame, epoch and optionally known byte hashes. Unretrieved legacy geometry_ref remains uncharacterized and cannot be used for physical geometry calculation. A causal new geometry requires actual pinned bytes and an authorized characterization profile. Longitude sign/range, planetocentric versus planetographic latitude, mesh coordinates, height/depth datum and surface model are profile decisions, not defaults. An orbital location references a governed orbital domain/product, not a fake surface site; an asset trajectory references a product rather than a table of invented states.

Vertical_support separates NONE (not applicable) from UNKNOWN (not characterized), ALTITUDE, DEPTH_BELOW_SURFACE and PRESSURE_LEVEL. Known coordinate bounds preserve units/datum; missing datum prevents datum-dependent comparison. Instrument vertical sensitivity remains separate product/observation metadata and is not automatically interpreted as sampled depth. Underground volume, ring annulus, gas-giant pressure interval, irregular-body mesh and Titan altitude profile use the same typed relationships without body-specific columns.

PostGIS is deferred until a qualified requirement needs intersection/distance. Do not use Earth geography or SRID 4326 for Moon/Mars coordinates. A later optional geometry cache must bind an explicit body/frame/metric profile and pinned source geometry, be reproducibly derived and grant no epistemic scope. This choice follows the [PostGIS geography semantics](https://postgis.net/docs/geography.html). Navigation frames and ephemeris states remain supplied by governed NAIF/SPICE/Horizons products; the database stores references and coverage. See [NAIF frames](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/frames.html).

## 4. Time support and quantities

Scientific time_support retains single epoch and start/end lexemes, calendar/timescale references and an explicit kind UNKNOWN/LEXICAL/INSTANT/INTERVAL. Equal endpoints denote an instant when actually characterized, not an empty interval. UTC instant/range is optional and requires a parsing warrant; partial dates are never guessed midnight, year boundaries or UTC. Publication time, acquisition time, observation time, sample collection time, knowledge time and valid support are independent relationships. A valid/observation interval says when evidence applies, not when a physical world state started existing.

6D SIM_TIME and CALENDAR_YEAR remain exact original time bases. No Julian/UTC conversion is introduced into qualified 6D. Preserve SIM_YEAR_PLUS_2025_V1 where recorded; any future celestial epoch mapping is a new governed reference, not a replacement clock. Causal decision, authorization, effective and realized times are separate; an absent decision is absent, not copied from event time. Numeric projections preserve corresponding lexemes and all original source_times in exact archive bytes. Decision/authorization cannot follow realization; original 6D does not otherwise require a fabricated strict total order between every source epoch and decision time.

Operational association periods use nonempty finite-lower `[start,end)` numranges on the existing SIM_TIME axis; an unbounded upper end means continuing association, not missing time coerced to infinity as a scientific quantity. Association periods describe declared history, never activity scheduling. Range semantics follow [PostgreSQL ranges](https://www.postgresql.org/docs/18/rangetypes.html).

`wa_meta.finite` is unconstrained NUMERIC, rejects NaN/±Infinity, and introduces no fixed-scale rounding. The original typed Decimal byte representation remains hash authority. PostgreSQL numeric arithmetic/rounding must never reimplement 6D ROUND_HALF_EVEN or stochastic logic; [PostgreSQL numeric semantics](https://www.postgresql.org/docs/18/datatype-numeric.html) differ at rounding boundaries.

Units preserve exact baseline lexemes, including taxonomy/detection codes, scale factors, percent, wt%, mixed labels and missing units. Source NULL unit maps to NOT_SUPPLIED with no unit row, not DIMENSIONLESS. A conversion is legal only under a pinned conversion profile; the base schema performs none. A quoted production rate remains a rate, not a finite material stock. Numeric SQLite values are retained with original storage class and IEEE bits in legacy_row; a normalized NUMERIC representation cannot claim source precision that SQLite did not retain. Original uncertainty strings, bounds and NULL bound_operator remain unchanged. RANGE/BOUND legacy rows are not rewritten into guessed inequalities. Numeric use is BLOCKED until the consumer has sufficient interpreted kind/unit/bound support.

## 5. Empirical firewall and scientific governance

Sources are versioned bibliography; source_artifacts are actual custody records. REMOTE_REFERENCE_ONLY permits null hash/byte count and means unverified original bytes. It is not immutable Earth-reference custody and is not sufficient for an extrapolation warrant. The source assertion's own pinned metadata can be hashed without claiming the cited website was byte-verified. An assertion carries ontology, property, complete support, optional observation/sample/product references, units/value/uncertainty, epistemic class, confidence, source locator, legacy lineage, original preference and initial standing. Preference is not admission.

Support is explicit `(body,scope,location/sample/geometry,vertical,valid time,representativeness,warrant,resolution)`. Missing reference is not silently widened. The baseline includes 14 material-evidence SAMPLE rows with no sample_id, 13 material-evidence REGION rows with no region_id, 14 scientific FOOTPRINT assertions without region, and 68 MODEL_DOMAIN assertions without region. These become UNRESOLVED supports with their precise original scope/citation and no fabricated geometry. Their existence is representable losslessly, but location-specific generation is blocked. Known body scope does not imply homogeneous local properties. Sample chemistry does not imply body abundance; a nondetection does not imply zero below sensitivity.

Every preserved assertion (880) and material-evidence row (35) stays CANDIDATE. No science admission rows are generated merely by migration. Scientific admission is a separate governor-only append-only decision with global deterministic decision_ordinal, use contract, authorization, knowledge time and decision hash. The current standing view chooses explicit latest decision, or the recorded initial standing; this is governance status resolution, never numerical defaulting. Ontology and standing remain orthogonal.

Generation consumes exact assertion metadata and a particular ADMITTED decision for its use contract, at a pinned scientific_cutoff_ordinal. New binding must reference the latest applicable decision at that cutoff; later HOLD/REJECTED does not rewrite a historical realization. Changing future constraint standing creates a new realization/input identity. An exact support match is required, or an extrapolation warrant explicitly binds source assertion/support/body, target support/body, property, method, model family, uncertainty, authorization, explicit scientific knowledge ordinal and a byte-pinned scientific warrant. Warrant availability must be at or before the realization cutoff; a later warrant cannot retroactively authorize earlier generation. Warrants begin CANDIDATE and have their own target variant in the same scientific admission history. Latest-at-cutoff warrant standing/use must be explicitly ADMITTED; later HOLD/REJECTED blocks new current-cutoff use without rewriting historical bindings. Warrant decisions cannot predate recorded availability. No second scientific approval registry is added. CONTAINS, OVERLAPS, common property labels, shared units, repeated copies or common body never substitute for that warrant. Arbitrary local fictional values must be declared unconstrained/model-family selection in the policy, not presented as science-backed abundance.

Science lineage edges are typed assertion/observation/product/material inputs, acyclic. A material-evidence row constrains generation only through a separately governed assertion at exactly its own support, retaining abundance/rate/detection semantics and a typed material input; migration creates no such new assertion. At the pinned generation cutoff, all assertion/material parents must also be explicitly ADMITTED for the same use contract. A candidate parent cannot become known through derivation. Each assertion-parent support crossing needs its own qualified scientific relationship; unresolved parent support blocks generation. Source observation/product metadata remains reviewed provenance of the admitted claim, not automatic independent numerical evidence. They can cite comparative evidence from other bodies; that does not transport scope. Reconciliation preserves both competing claims and classification/reason. Supersession is acyclic, retains original records and never updates already consumed bindings. Coverage explicitly records unsupported/source-gap state. Knowledge events target one typed source/observation/product/assertion and retain their own chronology.

REAL_EVIDENCE is measurement standing, MODEL_INFERENCE is interpretation, DERIVED is an explicit transformation, and empirical-context REALIZED_OBSERVATION remains in science only with REAL context. Generated observations cannot be inserted into science by the normal world/runtime roles; those roles have no science INSERT grant. A trusted science writer could lie about a source, so scientific admission still requires governed review; SQL cannot certify scientific truth from a string label.

## 6. Fictional WORLD

The minimum generation chain is science constraint/admission → model version → policy version → seeded scenario/body realization → hidden whole-body/regional properties → site refinement → deposit. These are descriptors/storage, not an implemented generation engine. Model pins implementation/schema/model family/uncertainty. Policy pins its model, body/property, authorization, exact policy definition bytes/hash and schema-variable parameters; parameters must validate under parameter_schema_ref. No JSONB decoder may treat an unknown field as an operational default.

Realization pins scenario, model/policy, WORLD seed lineage, algorithm/key schema, scientific cutoff, consumed constraint digest and generated output digest. Site refinement preserves the same world/body and explicit refinement model/seed lineage. A local site cannot be generated independently in a way inconsistent with the parent realization. Body-level coherence and correlated cross-site geology remain generator contracts, not relational inference. Same site/geography in two worlds can have different hidden realizations; neither becomes REAL evidence.

Hidden_state is a bounded physical-property representation, not a universal fact/object table. Its property dictionary has only NUMBER/TEXT/CATEGORY/MODEL_REFERENCE with physical semantics/schema references. Known payload must match its domain; UNKNOWN has no payload. Finance, belief and decisions cannot be imported as hidden physical properties. Rich profiles/meshes stay governed external products referenced by MODEL_REFERENCE, rather than unconstrained JSON. There is no arbitrary Agent/asset/contract/object polymorphic ID.

No Agent receives WORLD seeds, realization IDs, hidden values, constraint-selection metadata, hidden hashes or hidden-before/after state. These remain privileged generation/audit inputs. Missions may interact with them through the existing trusted physical mechanism, then create separately realized observations.

## 7. Resource layers

| Layer | Stored authority | Dependence | Database representation |
|---|---|---|---|
| in-situ initial material | SCENARIO hidden finite physical truth, or explicit UNKNOWN | generated geometry/material/phase | world.deposit.initial_in_situ_quantity |
| remaining in-situ/extracted | REALIZED physical state projection | actual extraction history | run.stock_state |
| accessible material | conditional derived assessment, provenance-bearing | location/depth/environment and technology/capability | run.accessibility_assessment |
| recoverable material | project-specific derived/realized assessment | matching accessibility and realized project capability | run.recoverability_assessment |
| reserve | economic/institutional interpretation | governed economics and institutions absent here | run.reserve_interpretation, UNKNOWN/BLOCKED only |

These are different tables and contracts. Reserve has no quantity field in this design. Future mature reserve conversion requires a governed additive interface/profile and qualification, not an ENUM switch granting economics. Absent assessment yields UNKNOWN in a typed adapter; missing mandatory use contract yields BLOCKED. Neither yields zero or in-situ fallback.

Stock projections must reconcile remaining in-situ + cumulative extracted = initial in-situ for the qualified finite-stock closure. Accessibility and recovery known quantities share exact unit and event-coherent upper bounds; unknown upstream bounds cannot certify known downstream quantities. This is validation of existing physical results, not a second inventory ledger. For qualified 6D, remaining is recoverable remaining: derive depletion as `recoverable_initial - remaining`, and represent in-situ remaining as `in_situ_initial - depletion`, exactly as qualified boundary.py does. Preserve the original ResourceState bytes. Do not relabel its remaining field as initial in-situ stock.

Future natural replenishment/erosion/processing is not inferred or implemented. It would need an explicit realized physical source/loss contract and new versioned balance profile, while old finite-stock records remain unchanged. No finance row, invoice, capacity name, reserve interpretation, abundance assertion or sale creates physical stock.

## 8. Projects, assets and settlements

Project stores named existing identity and original runtime record. Project_location is a many-to-many time-bounded named-location association, optionally bound to an exact fictional body/site realization when local WORLD geology is involved; no lifecycle is implemented. Project_party distinguishes owner/operator/sponsor/financier organization references and periods without creating financial mechanics or assuming every organization is an Agent. Project stages investigate/prospect/develop/construct/operate/extract/process/transport/settle/fail/defer/abandon remain existing or later authorized lifecycle artifacts, not a new table-driven state machine.

Actor_reference identifies only existing AGENT/AGGREGATE/SYSTEM records; asset has fixed ENTITY_ASSET classification and no decisions/beliefs. Organization_reference is a durable named relationship endpoint, not a new economic Agent. Assets have realized installation event and event-qualified placement: stationary, mobile, in transit or orbital. A trajectory reference is required for later continuous movement calculations; the schema itself does not propagate it. Shared assets need not belong exclusively to one project or settlement.

Settlement is a persistent named aggregate separate from geography. It may occupy multiple sites/regions and share assets. Settlement_state stores declared stage and actual habitation capacity with known/unknown/blocked state, provenance and event. Installation does not imply availability or delivered service. Ownership/operation are relations; the minimal settlement_asset relation permits an organization endpoint but confers no legal recognition or control mechanism.

Population_origin is a finite aggregate cohort with real admitted origin reference and genesis event. Population_state is a realized placement snapshot, with Earth, resident, rotational, visitor, transit and deceased categories. Residence is not labour, qualified labour, available labour or a staffed operation. No individuals, jobs, hiring engine, births/deaths simulation or households are created. Origin/migration/source-admission and original transport artifacts remain traceable. Source population projections are an admitted upper bound, not unlimited new people. A complete exported cohort snapshot must reconcile the original finite conservation identity; storing a few positions does not qualify a population balance.

Body-local physical WORLD-dependent asset/settlement/population placement must be verified against the body realization bound to its run. A purely navigational or system/orbital placement may have no geological world binding; it still has explicit REALIZED run/event identity and must not cause a resolver to choose a default WORLD. System-level environmental physics would need a separately governed model, not a fabricated celestial body or generation record. A physical asset cannot simultaneously occupy contradictory intervals; a genuinely distributed infrastructure is represented by multiple physical assets or a later explicit distribution profile, not an overloaded single-location identity. A settlement can span sites; a person count cannot be duplicated into each site merely because a settlement has multiple location associations.

## 9. Causal/provenance contract

run.artifact archives original type-tagged 6D UTF8 canonical bytes and `kind:sha256` ref. It is not a universal entity superclass or event-sourcing platform: it neither executes nor reduces records. Exact type tags keep physical, financial, information, decision and event records distinct. No consumer may infer compatibility from identical JSON fields. Frozen Builds1–6C without a strict BoundaryManifest remain external byte-pinned historical sources (meta.source_snapshot/source artifact references); do not fabricate an execution manifest to load them into the strict 6D run family. A read-only successor audit adapter may wrap exact original records under explicit original-context metadata and LEGACY_TRACE_INCOMPLETE status, without claiming a new audit digest was their historical hash.

CausalEnvelope remains domain-neutral. Its relational projection carries run/event/epoch, actor/process/action references, times, context, reason and hashes; original_envelope_bytes retains all request/decision/information/receipt refs, full typed before/after rows, result, source/rule/parameter/scenario/random/lineage refs and source_times. `original_hash_material` is the original canonical tuple of dataclass fields excluding envelope_hash. It is NOT the full record bytes. SQL checks their separate SHA-256 values; the trusted serializer validates that hash material and indexed columns actually correspond to the original record. Re-encoding JSONB is forbidden.

A new envelope must have the existing list's contiguous ordinal, exact REALIZED run context, previous trace hash, matching previous post/current pre image hashes and nondecreasing realization time. Parent links must point to an earlier same-run envelope. The frozen validate_trace() remains responsible for typed complete pre/post state-image reconstruction, original artifact closure, policy/system/genesis rule/code bindings, source/hash identity and omitted transition detection. SQL hashes alone do not prove a valid trace. Capture/replay retains original code contract and kernel-tree hash; new storage/export code is not injected into a historical 6D kernel tree.

Epistemic_loop is a private optional index of an existing path, not a runtime loop executor. It ties an admitted receipt, optional original belief update, actual decision/snapshot, separate action authorization, realized consequence and subsequent possessed information. A loop with no subsequent information is OPEN and cannot be claimed closed. COMPLETE additionally requires validated trace linkage from that consequence to its subsequent observation/publication, lawful possession plus use admission for the next decision, exact actor/time links and receipt-to-snapshot closure. SQL guard handles identity/time checks; the pinned typed validator handles full original artifact relations. Physical SYSTEM/genesis transitions legitimately have no Agent decision and are excluded from this Agent-loop index.

The closed loop is admitted information → visible state/belief → decision → authorized action → realized consequence → subsequent observation → later admission. Neither an observation nor its publication implies belief. Authorization may precede realization, and an actor learns output only after existing scheduled own-output admission. WORLD audit records remain inaccessible at every step.

## 10. Admission and normal Agent access

Context_value and consumption_request persist audit projections with all governing use/context/time/scope/perspective/unit/role fields and exact original records. Exception flags, lexical source/effective times, full arrays, transformation versions and dependency receipts survive in original typed archive, even when not each has another table. Receipt verifies the exact resolved fingerprint and request. A KNOWN receipt requires matching scope/unit/role/context/time, ADMITTED standing and Agent perspective/possession-compatible source. UNKNOWN/BLOCKED has no payload and an explicit reason. A declaration failure is BLOCKED, not unknown neutral knowledge. Known zero is legal only as explicit evidence/state under its own units/provenance.

The authoritative runtime admission check still uses BoundaryManifest allowed_use_contracts, exact fixed resolver bindings and current possession/state. DB receipts do not bypass verify_receipt() freshness or automatically turn historical receipts into current permissions. An observation stored here is not granted to every Agent. Admission and possession are independent. Derived information must preserve source context, source/effective time, standing, method, uncertainty and dependency lineage; the database creates no default Bayesian prior or fallback unit.

Only trusted admission_writer writes agent_fact after the qualified validate_snapshot()/snapshot_facts() path and an attestation binding exact worker snapshot bytes, original receipt set, actor/run/effective time, producer contract and safe projection. The SQL guard checks actual requested concept, actor, POLICY use, state/value and time; it blocks hidden resource concepts and BLOCKED worker facts. It is not a semantic sanitizer for arbitrary payload strings. agent_snapshot retains the exact safe DecisionSnapshot originally archived as DECISION_STATE, including its separate original worker fingerprint. An audit content hash is never substituted for `decision-snapshot:period:DecisionSnapshot.fingerprint()`. The future integration must reuse the 6D positive resolver/use whitelist and worker isolation; adding a novel concept or revealing a source field is an approval/qualification change, not generic SQL extensibility.

The bounded Agent-facing fact view returns only `(actor,snapshot,fact_key,effective_time,state,value,admitted:concept)` for the single login-authorized current snapshot. The companion current_snapshot view returns the exact original safe DecisionSnapshot bytes, actor/snapshot/period/effective time. Neither exposes run/universe identifiers to the worker. No audit artifact bytes, private world identifier/seed/source hashes, arbitrary science candidates or trace delta is projected. Snapshot ref refers to that actor's validated original snapshot, not a hidden world digest. The view owner is NOLOGIN, has SELECT only on principal_binding, agent_snapshot and agent_fact, and creates its view under its own role; CREATE privilege is then removed. Agent group has no private base-table/schema privileges and no writer/auditor memberships.

RLS is ENABLED and FORCED on all world/run/info tables. Trusted physical/genesis/audit service roles are deliberately privileged; Agent logins must never inherit or SET ROLE to them. Agent-facing pool is distinct from WORLD/runtime pool. Login mapping uses session_user, not caller-supplied actor strings or custom GUCs. principal_binding authorizes exactly one run/actor/current snapshot/effective time per login, checked by foreign key and both view/RLS predicates. Only the existing scheduler/admission path advances that pointer; it is revocable access metadata, not another clock. Loaded historical/future snapshots remain inaccessible to the normal Agent login. No direct SQL, database credentials, catalog access, trace query or physical resolver is delivered to the Agent worker. The worker remains the existing isolated bounded-policy process. A trusted adapter issues only the bounded view query at the requested snapshot/time and refuses future snapshots before the existing scheduler admits them.

RLS is defense in depth, not a claim of perfect information-flow security against administrators or arbitrary SQL. PostgreSQL owners/superusers and integrity checks have special behavior, so raw Agent SQL and DML/FK-probing are excluded. See [RLS](https://www.postgresql.org/docs/18/ddl-rowsecurity.html) and [view ownership/security](https://www.postgresql.org/docs/18/sql-createview.html). Login identity survives SET ROLE; see [SET ROLE](https://www.postgresql.org/docs/18/sql-set-role.html). No SECURITY DEFINER executable query function, dynamic SQL, untrusted search_path or generic hidden-state accessor is introduced.

## 12. Determinism, export and scaling

An export pins schema version/DDL+contract hashes, source snapshots, authority commits, scenario/run and code contracts. Export tables in FK-topological families, then full primary-key C order; dump exact bytea as lowercase hex, UUID as lowercase canonical text, scientific numbers with a declared nonrounding text export profile, and 6D values exclusively from original canonical bytes. NULL and UNKNOWN are separate tokens; no COALESCE(value,0), missing-row-to-zero or unset unit-to-dimensionless. Include complete rows/edges/supersession/admissions needed to reconstruct the pinned cutoff. Hash a manifest of filename, byte count, digest in C filename order; do not hash machine timestamps, physical DB row order or DB-generated UUIDs.

Comparison runs retain 6D WORLD/POLICY seed separation, LOOM_COMPARISON_RANDOM_V1 and SHA256_FIRST64_DECIMAL_V1, identical controlled key material and Decimal context. Snapshot IDs/database insertion ordering must not enter random keys. NULL/SPARSE/RICH share controlled streams until admitted observations cause authorized divergence. Different hidden worlds before distinguishing observation cannot influence Agent output. New generation random-family semantics are not selected in this pass: model-specific schema must explicitly pin them, and the later 6E DLD must govern new fixture/input identities without changing qualified 6D hashes.

Likely largest tables: artifact byte payloads, causal envelopes/edges/parents, realized observations, context values/receipts, physical snapshots and possession/belief history. Body/frame catalogs are small. B-tree indexes serve body/property/support, run/event, reverse provenance and Agent-snapshot queries; range GiST serves declared temporal association lookup. The reduction pass removed 149 automatically generated low-value FK indexes: immutable targets cannot be routinely deleted/updated, so such indexes do not earn their write/storage cost. The 60 explicit/query-selected indexes plus primary/unique indexes cover actual planned access paths. Adding another index requires an observed query/qualification need.

No partitions are created initially. Run-history PKs include run_id, permitting later run-based partitioning without losing typed same-run foreign keys. A later governed online partition migration must check uniqueness/FK restrictions and byte-stable export; see [PostgreSQL partitioning](https://www.postgresql.org/docs/18/ddl-partitioning.html). Scientific immutable revisions may later partition by source snapshot/body with an explicit global-identity strategy; do not improvise one now. Large spatial products remain pinned external blobs; original 6D records are ordinary bytea/TOAST, not a proprietary object service. No billion-citizen table or distributed message/log framework is designed.

## 14. Forensic and scientific metadata encoding profiles

The raw row archive is a governed source encoding, not an ETL procedure. `LEGACY_ROW_TAGGED_JSON_V1` represents original_columns as an object keyed by exact source column name. Each value is an object with `ordinal` (zero-based source schema position), `storage_class` (NULL/INTEGER/REAL/TEXT/BLOB), and exactly the corresponding payload: NULL has none; INTEGER has signed base-10 `integer_lexeme`; REAL has sixteen lowercase hex digits `ieee754_be64` plus the shortest round-trip decimal `display_lexeme`; TEXT has lowercase `utf8_hex` preserving exact bytes and optional decoded text when valid; BLOB has lowercase `bytes_hex`. Do not normalize whitespace/Unicode or source column names. SHA-256 row_digest hashes canonical UTF8 JSON of this object with key sorting, ASCII escapes and separators `,`/`:` under this exact version. Original bit/text-byte fields are lossless authority; display_lexeme is not claimed original source-publication precision. The validator reconstructs that encoding and compares row_digest; PostgreSQL JSONB text rendering is not the hash input.

For the pinned baseline, INTEGER -> NUMERIC is exact; finite REAL -> normalized NUMERIC uses that shortest-round-trip decimal without additional rounding, with the original bits retained separately. Nonfinite values are forbidden in normalized authority quantities; a later changed source with such values must preserve its raw row and block/review numeric projection, never map it to zero. TEXT units/dates/source locators stay exact. NULL unit is NOT_SUPPLIED, NULL epoch remains absent/UNKNOWN, empty reported text remains empty lexical text. No temporal parsing or unit conversion is implied.

`SCIENCE_ASSERTION_METADATA_JSON_V1` is canonical UTF8 JSON with header `schema`, source snapshot SHA-256, exact SQLite table/key, forensic row digest and complete normalized non-digest assertion/support/source projections. Numeric projections are decimal strings, UUIDs lowercase canonical text, enums exact strings, null explicit, keys sorted with ASCII escaping and `,`/`:` separators. metadata_bytes is the exact resulting encoding and metadata_sha256 its byte digest. It binds both original source and normalized interpretation without claiming the original remote source was downloaded. Any changed interpretation requires a new governed revision/hash. This new science profile never replaces the qualified 6D canonical serializer, snapshot fingerprint or receipt/envelope hashes.

Policy definition bytes use the pinned model parameter schema/profile recorded by model/policy, with exact byte SHA check; the variable JSONB projection must agree with those bytes under that profile. Selection of an actual generator/model/profile belongs to the later authorized 6E design, not a database-generated default. These profile rules settle field meaning and deterministic identity; the next pass still designs extraction, transaction/load procedure and validation evidence.
