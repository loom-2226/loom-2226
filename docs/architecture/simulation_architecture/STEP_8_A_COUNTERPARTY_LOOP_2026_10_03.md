# Step A - Counterparty recruitment loop

**NON_CANON / UNPROMOTED / EXPLORATORY ONLY**

## Boundary

An EXPLORE proposition may decompose into typed dependency-discovery requests and recruit a bounded neighborhood of eligible autonomous counterparties. Recruitment and response do not create a contract, commitment, project, capability, access right or physical consequence.

Implemented request types include OFFTAKE_REQUEST, TRANSPORT_REQUIREMENT, FINANCING_REQUEST, UNDERWRITING_REQUEST, SUPPLIER_REQUEST, CERTIFICATION_REQUEST, REGISTRY_REQUEST and INFORMATION_REQUEST. Existing activation vocabulary remains available for other causal lanes.

Each originating actor category has an explicit dependency-discovery template. These templates determine what the actor investigates; they do not assert that every requested dependency will be a mandatory transaction gate. Step B determines concrete feasibility requirements.

## Recruitment

For each target role, candidate selection is bounded by jurisdiction:
- up to two domestic candidates;
- up to one GLOBAL/multinational candidate;
- up to one cross-border fallback candidate.

Candidate ordering is deterministic and uses the existing estimated 2026 capacity only to bound/order the exploratory neighborhood. Selection proves neither affordability nor capability.

Only functional, autonomous-eligible actors may be recruited. A request marks them RELEVANT to the request context and carries proposition/context provenance. It never promotes ACTIVE_TRANSACTIONAL.

## Response

Recruited actors run a bounded exploratory-response portfolio. The implemented dispositions are ACCEPT_EXPLORATION, DEFER, DECLINE and reserved COUNTER. ACCEPT_EXPLORATION means only that the actor allocates attention to investigate the request. DEFER represents an attention constraint. DECLINE currently represents failure of exploratory affordability. COUNTER is reserved for Step B term-bearing responses, because inventing a counteroffer before terms exist would be decorative nonsense.

Response capacity uses the same scale-derived bounded attention contract as proposition formation. Deterministic request identity provides stable tie breaking without invented actor psychology.

## First real-Earth acceptance test

Source proposition: Honeybee Robotics (Blue Origin), a current autonomous PROSPECTOR candidate, EXPLORE decision on EARTH:2026:AUS:BULK_MATERIALS.

Observed:
- 11 typed requests;
- 11 distinct target roles;
- 21 distinct recruited autonomous counterparties;
- 21 ACCEPT_EXPLORATION responses in this single-proposition test;
- request and response provenance retained;
- deterministic replay passes;
- target-category and autonomous-eligibility firewalls pass;
- zero recruited actor has consequential-action authority.

Illustrative recruited actors include Macquarie Group (capital), Munich Re (insurance), SpaceX (carrier), ArcelorMittal (offtake), BHP (incumbent/supplier exploration), Airbus Defence and Space (supplier prime), ALS/CRIRSCO and other certification candidates, and information/regulatory candidates.

The presence of a recruited or accepting actor is not evidence that the proposition is technically, financially, legally or physically feasible.

## Step B handoff

Step B may consume accepted exploratory responses to construct a proposition feasibility state. It must independently test concrete requirements against existing actor budget, capability, access, transport, insurance/certification/regulatory and project/service authorities before any commitment or project can exist.

Hard firewall:

REQUEST != AGREEMENT.
ACCEPT_EXPLORATION != CONTRACT.
COUNTERPARTY INTEREST != CAPABILITY.
COUNTERPARTY INTEREST != SPENDABLE BUDGET.
ASSEMBLED PROPOSITION != COMMITTED PROJECT.
